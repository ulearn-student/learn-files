# 02-mvp-scope.md · MVP 功能范围

> 三角洲战友匹配平台
> 用 MoSCoW 法则划分 V1.0 范围

---

## MVP 核心假设(必须验证的 3 件事)

```
假设 1: 三角洲玩家愿意花 1 分钟做"性格作风测试"
假设 2: 三角洲玩家打完一局后会主动评分
假设 3: 基于性格 + 评分的匹配, 比腾讯官方匹配更让用户满意
```

**MVP 的所有功能,必须为验证这 3 个假设服务。**
**不为这 3 个假设服务的功能,一律砍掉!**

---

## 🔴 Must Have(V1.0 必须有,5 个)

| # | 功能 | 验证哪个假设 |
|---|---|---|
| 1 | 用户注册(邮箱/微信,30 秒搞定) | 是用户进入系统的入口 |
| 2 | 玩法标签(跑刀 / 猛攻 二选一) | 假设 1 - 用户愿意分类自己 |
| 3 | 匹配推荐页(系统推 3 个候选人) | 假设 3 - 核心匹配体验 |
| 4 | 候选人详情(玩法标签 + 信用分 + 段位) | 假设 3 - 决策依据 |
| 5 | 队友评分(打完一局,强制 5 秒评分) | 假设 2 - 评分机制 |

**MVP 闭环:注册 → 标签 → 匹配 → 评分 → 形成数据飞轮**

---

## 🟡 Should Have(V1.5 加上)

| # | 功能 | 为什么 V1.5 |
|---|---|---|
| 6 | 作风测试(5 道题,细化性格画像) | V1 用玩法二分法够用,先验证基础 |
| 7 | 互选机制(双方都点"想一起玩"才换 ID) | V1 单向选就行,简化流程 |
| 8 | 信用分排序(高分玩家优先推荐) | V1 用户少没数据,先随机推荐 |

---

## 🟢 Could Have(V2.0 锦上添花)

| # | 功能 | 为什么 V2 |
|---|---|---|
| 9 | 邀请朋友解锁 VIP 匹配 | 增长机制,有了基础用户再做 |
| 10 | 战绩同步(对接游戏接口) | 需要研究游戏 API,先用手填 |
| 11 | 战队系统(固定 4 人组队) | 等用户能稳定组 2 人队再考虑 |

---

## ⚫ Won't Have(永不考虑)

| # | 功能 | 为什么不做 |
|---|---|---|
| 12 | 平台内开麦语音 | 用游戏自带语音即可,造重复轮子 |
| 13 | 举报违规 + 截图审核 | 个人开发者人工审核做不了 |
| 14 | 视频/对话 AI 审核 | 技术贵 + 隐私问题 |
| 15 | 变声器 | 破坏真实信任,与产品价值观冲突 |
| 16 | 实名认证 | 玩家反感,且 MVP 不需要 |
| 17 | 付费会员墙 | 核心功能必须免费 |

---

## 功能合并说明

为了把 Must Have 控制在 5 个,以下功能采用合并实现:

```
原 8 (评分) + 原 9 (强制弹出) = 现 5 (队友评分含强制弹出)
原 10 (信用分系统) → 简化为"信用分显示" → 包含在 4 候选人详情中

砍掉的: 原 3 (作风测试) → 移到 Should Have
```

## 验证标准

MVP 上线后,如何判断是否成功?

```
✅ 成功标准 (满足任意 1 条算成功):

技术指标:
  - 至少 20 个真实用户注册
  - 平均每用户使用 > 3 次
  - 用户评分参与率 > 50%

产品指标:
  - 至少 5 个用户找到固定搭子
  - 用户主动推荐(口碑传播)
  - 收到至少 10 条用户反馈

学习指标:
  - 这个项目成功放进简历
  - 面试时能流畅讲清楚架构
```

```
❌ 失败信号 (任一出现需要重新思考):

  - 注册 < 10 人(冷启动失败)
  - 评分参与率 < 20%(假设 2 错了)
  - 用户匹配后 0 次再回来(假设 3 错了)
```

## 决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| Must Have 数量上限 | 5 个 | 避免功能蔓延 |
| 作风测试是否进 V1 | 否 | 玩法二分法够用,先简化 |
| 是否做开麦 | 否 | 游戏自带语音,重复造轮 |
| 评分是否强制 | 是 | 不强制就没数据 |
| 信用分是否在 V1 显示 | 是 | 简单实现,价值大 |

---

## 防止"功能蔓延"的承诺

```
开发过程中, 如果我突然想"再加一个功能", 请回答:

Q1: 这个功能能验证我的 3 个核心假设吗?
Q2: 没有它, 用户完全用不了产品吗?
Q3: 这个功能现有方案替代不了吗?

→ 任何一题答"否", 这个功能就要进 V2 或 Won't Have
→ 决不在 V1 阶段加新功能!
```
